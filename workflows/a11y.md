# Accessibility Audit

## Step 0 — Determine the platform

**Do this first.** The rules are almost entirely different, and auditing native
code against web rules produces confidently wrong findings.

Read the platform standard imported by the project's agent instruction file, or infer from
the source: `standards/platform/web.md` for DOM-based apps, `standards/platform/native.md` for React
Native. If a monorepo contains both, audit them separately and label findings.

---

## Web audit

Target WCAG 2.1 AA. Thresholds in `standards/core/rules.md`.

**Accessible names**
- Buttons with no visible text and no `aria-label`
- Inputs and selects with no associated `<label>` and no `aria-label`
- Icon-only controls
- Links whose only content is an icon or the word "here"

**Hidden from assistive tech**
- Decorative icons and SVGs missing `aria-hidden="true"`
- Images missing `alt` entirely (decorative ones need `alt=""`, not no attribute)

**Semantics**
- `<div onClick>` / `<span onClick>` where `<button>` belongs
- Div-based lists that should be `<ul>`/`<ol>`
- Layout tables
- Buttons in forms without an explicit `type`
- `aria-label` on a role-less `<div>` — silently ignored by screen readers
- Heading levels skipped or used for visual sizing

**Keyboard and focus**
- Click handlers on non-interactive elements with no key handler
- `outline: none` with no visible replacement
- Modals and drawers that do not trap focus, or do not restore it on close
- Positive `tabindex` values
- Focus moved without user initiation

**Forms**
- Errors not linked via `aria-describedby`
- Required fields not marked
- Validation communicated by color alone

**Contrast**
- Text below the ratio in `standards/core/rules.md` against its real background
- Information conveyed by color alone anywhere

## Native audit

No DOM, so nothing is accessible by default and no tooling catches it.

- Touchables missing `accessibilityLabel`
- Missing or wrong `accessibilityRole`
- Composite elements without `accessible={true}`, announced as fragments
- `accessibilityState` absent on selected/disabled/checked/expanded controls
- `accessibilityHint` missing where the outcome is not obvious
- Touch targets under the minimum in `standards/core/rules.md` with no `hitSlop`
- `allowFontScaling={false}` on body text
- Fixed-height containers that clip at large font scales
- Custom gestures with no accessible alternative
- Decorative images not marked `accessibilityElementsHidden`

---

## Output

Group by file. Per finding: **`file:line`**, what breaks and **for whom**, and
the fix.

End with a total and a prioritized list, ordered by user impact:

1. **Blocks a user entirely** — unlabeled control, keyboard trap, unreachable content
2. **Degrades significantly** — wrong role, missing state, poor focus order
3. **Minor** — redundant announcements, missing hints

Automated inspection cannot verify screen-reader focus order, announcement
quality, or gesture conflicts. State this explicitly and recommend a manual pass
with the relevant screen reader — do not let the audit imply full coverage.

## Anti-patterns

❌ A test-only attribute in place of an accessible name
❌ `aria-label` on an element with no role
❌ Replacing a visible label with `aria-label` — sighted users need it too
❌ Applying web rules to native code
